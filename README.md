# Бот «Аптечка состояний» — подписка + управление офферами из Telegram

## Как работает воронка
1. Человек приходит по ссылке `https://t.me/ИМЯ_БОТА?start=КОД`.
2. Бот сохраняет его в базу и показывает **оффер** этого кода: картинка + текст + 2 кнопки.
3. **«Проверить подписку ↗»** — открывает канал.
4. **«Я подписана ✅»** — реально проверяет подписку через Telegram API:
   - подписан → бот выдаёт материал (ссылку или файл);
   - не подписан → всплывашка «подпишись и нажми ещё раз».

## Управление офферами — прямо в Telegram, без кода и GitHub
Офферы и материалы хранятся в базе Postgres. Файлы (картинки, PDF) живут в самом
Telegram — бот запоминает их `file_id` и пересылает заново. Ничего никуда заливать не нужно.

Команды (только для админов из `ADMIN_IDS`):
- `/newoffer` — добавить/перезаписать оффер. Мастер из 4 шагов: код → картинка → текст → материал
  (ссылку пишешь текстом, файл — присылаешь документом).
- `/offers` — список всех офферов.
- `/testoffer КОД` — показать, как выглядит оффер.
- `/deloffer КОД` — удалить оффер.
- `/cancel` — отменить добавление.
- `/stats` — число пользователей.
- `/broadcast` — рассылка (текстом или ответом на сообщение).

Текст оффера можно форматировать прямо в Telegram (выделить → жирный/курсив) — сохранится.

## Переменные окружения (Railway → Variables)
| Переменная         | Пример                              | Зачем |
|--------------------|-------------------------------------|-------|
| `BOT_TOKEN`        | `12345:AA...`                       | токен от @BotFather |
| `ADMIN_IDS`        | `7507890517,8194805214`             | id админов через запятую |
| `DATABASE_URL`     | (Railway подставит сам)             | подключение к Postgres |
| `REQUIRED_CHANNEL` | `@my_channel` или `-1001234567890`  | канал для проверки подписки |
| `CHANNEL_URL`      | `https://t.me/my_channel`           | ссылка на канал для кнопки |

Публичный канал → `@username` + `https://t.me/username`.
Приватный канал → числовой `-100...` id + пригласительная ссылка `https://t.me/+...`.

## ⚠️ Обязательно: бот должен быть админом канала
Без прав администратора `getChatMember` не работает и проверка всегда вернёт «не подписан».
Числовой id приватного канала: перешли любой пост из канала боту @userinfobot.

## База данных
- `users` — пользователи (как раньше).
- `offers` — офферы: `code, image_file_id, text, material_type ('url'|'file'), material_value, active`.

Таблицы создаются автоматически. При первом запуске офферы `MATERIAL1..3` засеиваются
со старыми ссылками (без картинок) — чтобы уже разосланные ссылки работали. Обложки
и тексты допиливаешь через `/newoffer` (тот же код перезапишет оффер).

## Примечание
Состояние мастера `/newoffer` хранится в памяти. Если бот перезапустится прямо в процессе
добавления оффера — просто начни `/newoffer` заново. На уже сохранённые офферы это не влияет.

## Запуск на Railway
Стартовая команда задана в `Procfile`: `worker: python bot.py`.
